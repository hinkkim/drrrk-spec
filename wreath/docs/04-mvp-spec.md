# 04. MVP 서비스 기획

> 전제: 시장 검증([03](03-validation-plan.md)) Go 판정 이후 실행.
> 원칙: **Phase 1은 소프트웨어가 아니라 운영이다.** 카카오톡 채널 + 스프레드시트로 컨시어지 운영을 먼저 하고,
> 반복이 증명된 플로우만 Phase 2에서 제품화한다.

---

## 1. MVP 범위 (리서치 17-4 기반, 조정)

```text
B2B 시설 등록
+ 수거 요청 (또는 정기 스케줄)
+ 지역 파트너 배차
+ 수거 완료 인증 (사진·수량)
+ 유족 동의 기록 (장례식장 한정) ← 리서치 대비 추가: 규제 정렬 기능은 MVP에 포함
+ 수거 이력 조회
```

**Out of scope (Phase 3 이후):** 분해·분류 데이터, 재사용 소재 DB, ESG 리포트 자동화, 수거업체 정산 자동화, 유족 대상 B2C 접점.

---

## 2. 사용자와 역할

| 역할 | 사용자 | 주요 행동 |
|---|---|---|
| 시설 담당자 | 웨딩홀 지배인, 장례식장 사무장 | 수거 요청, 동의 기록, 이력 확인 |
| 시설 본사 관리자 | 다지점 운영사 본사 | 지점별 현황·이력 대시보드 |
| 수거 파트너 | 지역 수거업체 기사/사장 | 배차 수락, 수거 인증 |
| 운영자 (우리) | 내부 | 배차 관리, 파트너 관리, 예외 처리 |
| (참조) 유족 | 상주 | 동의 서명 — 시설 담당자 기기에서 처리, 별도 앱 없음 |

---

## 3. 핵심 플로우

### F1. 수거 요청 → 완료

```text
[시설] 수거 요청
  · 건별: "○홀 예식 종료, 화환 24개" / "○호실 발인, 화환 12개"
  · 정기: "매주 토 18시 일괄" 스케줄 등록
      ↓
[시스템] 지역·시간대 기준 파트너 매칭 (Phase 1: 운영자 수동 배차)
      ↓
[파트너] 배차 수락 → 예상 도착 시간 공유
      ↓
[파트너] 현장 수거 → 인증 등록
  · 수거 전/후 사진
  · 수량 (프레임 수 기준)
  · 상태 분류: 프레임 회수 가능 / 파손 / 생화 폐기
      ↓
[시설] 완료 확인 → 이력 자동 기록
```

### F2. 유족 동의 (장례식장 전용)

```text
[시설 담당자] 빈소 등록 시 화환 처리 안내 화면 제시
      ↓
[유족] 처리 방식 선택
  · 전량 위탁 처리 (파쇄·자원화 인증)
  · 일부 인수 (리본·생화 일부 등)
  · 자체 처리
      ↓
[유족] 서명 (담당자 태블릿/폰)
      ↓
동의서 PDF 자동 보관 → 수거 이력과 연결
```

> 이 플로우가 권익위 권고(유족 사전 동의) 대응 기능이며, 장례식장 영업의 핵심 훅이다.

### F3. 처리 인증 (절충 정책 반영)

```text
수거 완료
  ↓
집하/분해: 생화 ↔ 프레임·거치대·부자재 분리
  ↓
생화 → 파쇄·퇴비화·업사이클 (재사용 금지 원칙)
프레임·거치대 → 회수 재사용 풀
  ↓
처리 결과 등록 → 시설·(요청 시) 유족에게 인증 리포트
```

## 4. 기능 명세 (Phase 2 제품화 기준)

### 시설용 (모바일 웹)
- 시설/지점/담당자 등록, 수거 요청(건별·정기), 요청 현황판
- 유족 동의 등록·서명·PDF 보관 (장례식장)
- 수거 이력: 일자·수량·사진·처리 결과, 월간 요약
- 알림: 카카오 알림톡 (배차 확정, 수거 완료)

### 파트너용 (모바일 웹)
- 배차 알림 → 수락/거절, 당일 수거 목록·동선
- 수거 인증 업로드 (사진·수량·상태)
- 월간 수거 실적 조회

### 운영 어드민
- 배차 보드 (수동 배차 + 규칙 기반 추천), 파트너/시설 관리
- 예외 처리 (노쇼, 수량 불일치, 파손 분쟁)
- 지표 대시보드 (5장 KPI)

---

## 5. MVP KPI

| KPI | 정의 | 초기 목표 (파일럿 8주) |
|---|---|---|
| 활성 시설 수 | 주 1회 이상 요청 시설 | 5곳 |
| 수거 완수율 | 요청 대비 기한 내 수거 완료 | 95%+ |
| 요청→수거 리드타임 | 건별 요청 기준 | 웨딩 4h / 장례 발인 후 당일 |
| 인증 등록률 | 수거 건 중 사진·수량 등록 비율 | 90%+ |
| 동의 기록률 | 장례 수거 건 중 유족 동의 확보 비율 | 100% |
| 건당 공헌이익 | (회수가치+서비스료) − (물류+처리비) | > 0 |
| 시설 리텐션 | 4주 후 계속 사용 | 100% (5곳 중 이탈 0) |

## 6. 데이터 모델 개요

```text
Facility (시설)          — 유형(웨딩/장례), 지점, 담당자, 계약 조건
Partner (수거 파트너)     — 커버 지역, 차량, 처리 능력, 정산 조건
PickupRequest (수거 요청) — 시설, 일시, 예상 수량, 건별/정기, 상태
Dispatch (배차)          — 요청↔파트너, 수락/도착/완료 타임스탬프
PickupProof (수거 인증)   — 사진, 수량, 상태 분류
Consent (유족 동의)       — 빈소, 처리 방식 선택, 서명, PDF
Processing (처리 결과)    — 분해 내역, 처리 경로(파쇄/퇴비화/업사이클/재사용), 인증
LedgerEntry (정산 원장)   — 건당 비용·수익 기록 (공헌이익 계산용)
```

- 모든 엔티티는 화환 "개수" 단위가 아니라 **수거 건(Request) 단위**로 연결하고, 개수는 인증에서 기록 — 현장 카운팅 부담 최소화.
- Consent와 PickupProof의 연결이 이 제품의 규제 대응 가치이므로 초기 스키마부터 필수 관계로 설계.

---

## 7. Phase 1 컨시어지 운영 (제품 없이 시작)

| 기능 | 대체 수단 |
|---|---|
| 수거 요청 | 카카오톡 채널 / 전화 |
| 배차 | 운영자가 파트너에 직접 연락 |
| 인증 | 파트너가 카톡으로 사진 전송 → 운영자가 시트 기록 |
| 동의 기록 | 종이 동의서 양식 + 스캔 |
| 이력 리포트 | 월말 스프레드시트 → PDF 발송 |

> Phase 1의 목적은 매출이 아니라 **단위 경제성 실측과 플로우 검증**이다.
> 8주 운영 데이터로 5장 KPI가 확인되면 Phase 2 제품화에 착수한다.
