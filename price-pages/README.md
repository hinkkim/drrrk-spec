# 품목별 시세 페이지 생성기

React SPA(Vite/CRA)를 **전혀 건드리지 않고** 검색 유입용 정적 페이지를 붙이기 위한 도구입니다.

```
data/items.json  →  build.mjs  →  dist/price/*.html + sitemap-price.xml
```

---

## 왜 이 구조인가

`drrrk.ai.kr` 은 React SPA입니다. SPA는 크롤러에게 빈 `<div id="root">` 하나로 보이기 때문에,
앱 안에 아무리 텍스트를 넣어도 검색 색인에 잡히지 않습니다.

그렇다고 앱 전체를 SSR로 옮길 필요는 없습니다. **색인이 필요한 페이지는 랜딩·FAQ·품목별 시세
세 종류뿐**이고, 로그인 후 화면은 어차피 색인 대상이 아닙니다. 그래서 이 세 종류만 완전한
정적 HTML로 뽑아 같은 도메인에 얹는 방식이 가장 싸고 빠릅니다.

서브도메인(`price.drrrk.ai.kr`)은 권하지 않습니다. 도메인 권위가 갈라져서 본 사이트가 쌓은
신뢰를 물려받지 못합니다. 반드시 `drrrk.ai.kr/price/...` 하위 경로로 두세요.

---

## 실행

```bash
cd price-pages
node build.mjs                 # dist/ 에 생성
node build.mjs --out ../public # 출력 위치 지정
```

의존성 없음. Node 18 이상이면 됩니다.

빌드 시 두 가지를 자동 검사하고, 걸리면 즉시 실패합니다.

- **슬러그 중복** — 조용히 덮어쓰이면 페이지가 통째로 사라집니다
- **`related` 참조 무결성** — 깨진 내부 링크는 그대로 SEO 손해입니다

---

## 배포 — 두 가지 경로

### 경로 A. SPA의 `public/` 에 넣기 (권장)

Vite와 CRA 모두 `public/` 안의 파일을 **가공 없이 그대로** 빌드 결과에 복사합니다.
인프라를 건드릴 필요가 없습니다.

```jsonc
// SPA 레포의 package.json
{
  "scripts": {
    "build:price": "node ../drrrk-spec/price-pages/build.mjs --out ./public",
    "build": "npm run build:price && vite build"
  }
}
```

이러면 배포할 때마다 시세 페이지가 함께 갱신됩니다.

### 경로 B. 별도 Vercel 프로젝트 + rewrite

시세 페이지를 앱 배포 주기와 분리하고 싶을 때 씁니다. 데이터가 자주 바뀌면 이쪽이 낫습니다.

```jsonc
// 메인 프로젝트 vercel.json
{
  "rewrites": [
    { "source": "/price/:path*", "destination": "https://drrrk-price.vercel.app/price/:path*" }
  ]
}
```

---

## Vercel 설정

`vercel.json` 예시는 이 폴더의 [`vercel.json`](./vercel.json) 을 참고하세요. 핵심은 두 가지입니다.

**1. `cleanUrls`** — `/price/샤넬-클래식-플랩-미디움.html` 을 `.html` 없이 서빙합니다.

**2. SPA catch-all rewrite와의 순서** — Vercel은 `rewrites` 보다 **파일시스템을 먼저** 확인합니다.
따라서 실제 파일이 존재하는 `/price/*` 는 SPA catch-all에 잡히지 않습니다. 다만 의도를 명시해
두는 편이 안전하므로, catch-all에서 `price` 를 제외한 형태를 함께 넣어뒀습니다.

배포 후 **반드시** 확인하세요.

```bash
curl -s https://drrrk.ai.kr/price/샤넬-클래식-플랩-미디움 | grep "중고 시세"
```

여기서 텍스트가 나오면 성공입니다. 안 나오면 SPA로 넘어간 것이니 rewrite 순서를 확인하세요.

## 데이터 스키마

`data/items.json` 의 `items[]` 각 항목입니다.

| 필드 | 필수 | 설명 |
|---|:---:|---|
| `slug` | ● | URL 경로. 한글 그대로 씁니다 |
| `slugEn` | | `slugMode: 'ascii'` 로 전환할 때 쓰는 영문 슬러그 |
| `brand` / `brandEn` | ● | 샤넬 / CHANEL |
| `model` | ● | 클래식 플랩 미디움 |
| `spec` | ● | 캐비어 · 금장 |
| `category` / `categorySlug` | ● | 명품 가방 / 명품가방 |
| `low` / `high` | ● | 시세 범위 (원 단위 정수) |
| `period` | ● | "최근 90일" 등 산출 기간 |
| `sampleSize` | ● | 표본 건수 |
| `delta` | ● | 전월 대비 % (음수 가능) |
| `grades[]` | ● | `{grade, desc, low, high}` |
| **`factors[]`** | ● | **이 모델 고유의 가격 결정 요인** |
| **`checkpoints[]`** | ● | **이 모델 고유의 검수 체크포인트** |
| **`faq[]`** | ● | **이 모델 고유의 Q&A** — `{q, a}` |
| `related[]` | | 함께 조회한 자산 슬러그 3개 |

### 굵게 표시한 세 필드가 이 도구의 핵심입니다

프로그래매틱 SEO가 실패하는 이유는 거의 항상 하나입니다 — **템플릿으로 찍은 페이지가 전부
같은 문장이라 중복 콘텐츠로 판정되어 색인에서 빠지는 것.**

`factors` / `checkpoints` / `faq` 는 품목마다 다를 수밖에 없는 내용이라, 이 셋만 성실히 채우면
페이지 고유성이 자동으로 확보됩니다. 현재 샘플 9장 기준 측정값:

```
페이지당 고유 문장 비율   61 ~ 68%
페이지 쌍 최대 유사도     24%
본문 분량               1,455 ~ 1,594자
```

**`factors` 를 복사·붙여넣기로 채우면 이 도구는 무용지물이 됩니다.** 품목당 3~4개, 그 모델을
실제로 다뤄본 사람이 아는 내용을 쓰세요. 그게 이 페이지의 유일한 자산입니다.

## 구조화 데이터

각 페이지에 `BreadcrumbList` 와 `FAQPage` 를 넣습니다.

**`Product` + `offers` 는 의도적으로 넣지 않았습니다.** 이 페이지는 상품을 파는 페이지가 아니라
시세를 안내하는 페이지입니다. 구매 가능한 offer가 없는 상태에서 Product 마크업을 붙이면
구조화 데이터 정책 위반으로 리치 결과에서 제외될 수 있습니다. 같은 이유로 `AggregateRating` 도
실제 리뷰 데이터가 페이지에 노출되기 전까지는 넣지 마세요.

## 배포 후 할 일

1. **`robots.txt` 에 사이트맵 등록**

   ```
   Sitemap: https://drrrk.ai.kr/sitemap-price.xml
   ```

2. **Google Search Console** 에 사이트맵 제출 → 색인 현황 추적

   GSC가 등록돼 있지 않다면 이것부터 하세요. 없으면 무슨 작업을 해도 결과를 볼 수 없습니다.

3. **2~4주 후 확인** — GSC 실적 보고서에서 `/price/` 경로의 노출수와 유입 검색어를 봅니다.
   노출은 있는데 클릭이 없으면 `title` / `description` 문제, 노출 자체가 없으면 색인 또는
   콘텐츠 문제입니다.

## 확장 순서

지금 샘플 9장은 **구조 검증용**입니다. 실제 운영은 이 순서를 권합니다.

| 단계 | 규모 | 목적 |
|---|---|---|
| 1 | 20장 | 실데이터로 채우고 색인 여부·유입 검색어 확인 |
| 2 | 100~300장 | 유입이 확인된 카테고리 위주로 확장 |
| 3 | 자동화 | DB/시트 → `items.json` 파이프라인 연결, 주기 배포 |

1단계에서 유입이 전혀 없으면 규모를 늘려도 똑같습니다. **20장으로 먼저 검증하고 늘리세요.**

---

## 주의

`data/items.json` 의 **시세·건수·등락률은 전부 예시값**입니다. 실데이터로 교체하지 않은 채
배포하면 안 됩니다.

시세 표기에는 항상 **산출 기간과 표본 수**를 함께 노출하도록 템플릿을 짰습니다
(`최근 90일 실거래 342건`). 표본이 적을 때도 이 표기를 유지하세요. 근거 없는 단정보다
표본을 밝힌 범위 제시가 정직하고, 표시광고법상으로도 안전합니다.
