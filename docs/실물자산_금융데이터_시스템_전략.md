## 1. 확정된 프레임 — DRRRK = Asset Bureau

DMCC 조사에서 도출된 최종 포지셔닝:

> **NICE/KCB는 사람을 Score한다.**
> **DRRRK는 자산을 Score한다.**
> **DMCC Tradeflow는 그 자산을 실제 담보로 만들 수 있는 Rail을 제공한다.**

UAE 사업 구조는 3-Layer로 확정적으로 분리된다:

| Layer | 담당 | 답하는 질문 |
|---|---|---|
| **Layer 1 — Collateral Rail** | DMCC Tradeflow | "이 자산이 법적으로 존재하고, 담보 설정 가능한가?" (존재·소유권·점유·pledge·법적 집행력) |
| **Layer 2 — Asset Underwriting** | **DRRRK** | **"이 자산은 얼마이고, 얼마나 유동적이며, 얼마까지 안전하게 금융할 수 있는가?"** |
| Layer 3 — Capital | Bank / Islamic Finance Co. | 신용심사·승인·LTV 최종 결정·자금 공급 (CBUAE 감독) |

이 구조의 함의:

1. **드르륵은 lender가 될 필요가 없다.** Credit Decision은 금융기관 고유 권한(아웃소싱 불가 영역)이고, 드르륵이 넘보면 규제 리스크만 커진다. 드르륵의 산출물은 대출 승인이 아니라 **자산 데이터**다.
2. **샤리아는 담보(Rahn)를 금지하지 않는다.** 금지되는 것은 금전대차에 이자를 붙이는 것. Conventional Rail(이자부 담보대출)과 Islamic Rail(Murabaha + Rahn)이 모두 존재하며, 드르륵의 Asset Score는 양쪽 Rail에 동일하게 공급 가능하다 — 금융 구조 설계는 Layer 3의 일이다.
3. **White space 확인됨**: DMCC Tradeflow는 B2B commodity/inventory 중심. **개인 보유 비정형 프리미엄 자산(Rolex, Hermès 등)의 valuation·liquidity·underwriting 레이어는 비어 있다.** (단, 개인 자산의 Tradeflow Warrant 편입 가능 여부는 UAE 측 확인 필요 — §5의 3대 질문.)

## 2. 핵심 구분 — Market Value가 아니라 Liquidation Value

금융기관이 담보에 대해 궁금한 것은 "시세"가 아니다:

> "이 Rolex를 우리가 회수했을 때, **30일 안에 확실하게 얼마에 현금화할 수 있는가?**"

| 구분 | Market Value | Liquidation Value |
|---|---|---|
| 정의 | 소매 시장 거래가 | 회수 상황에서의 신속 처분가 |
| 데이터 소스 | KREAM·Chrono24 등 sold 데이터 (공개, 누구나 접근) | **전문 바이어의 실제 매입 호가** (비공개, 드르륵만 보유) |
| 금융기관에게 | 참고치 | **의사결정 기준** |

**여기서 드르륵의 구조적 해자가 나온다: 드르륵의 역경매 견적·즉시팔기 입찰은 소매 시세가 아니라 전문 매입업자의 도매 호가(wholesale bid)다. 즉 Liquidation Value의 직접 관측치다.** 같은 자산에 바이어 4~5곳이 동시에 가격을 제시하면 그것이 실시간 wholesale demand curve이고, 이 데이터는 외부 어디에도 존재하지 않는다. KREAM 시세는 누구나 긁을 수 있지만, "회수 시 즉시 현금화 가능한 가격의 분포"는 드르륵의 거래 구조에서만 생산된다.

목표 산출물 — **DRRRK Asset Score** (자산 1건당):

```
Market Value            ₩15,200,000
30D Liquidation Value   ₩12,400,000
Net Recovery Value      ₩11,800,000   (처분 비용·소요 반영)
Bid Depth               5 quotes
90D Volatility          6.2%
Authentication Conf.    상 (실물 검수 완료)
Recommended Haircut     22%
Recommended LTV         55%
```

## 3. 국내에서 증명할 것 — Phase 로드맵

중동은 지금 실행할 시장이 아니라, **국내에서 무엇을 증명해야 하는지 역으로 알려주는 Destination**이다.

```
Phase 1. Korea — Market Validation      (현재: 역경매·견적·거래 플로우 가동)
Phase 2. Korea — Asset Underwriting     (★ 지금 만들 것: 원장 + Asset Score)
Phase 3. Korea — Financial PoC          (금융기관에 Underwriting 데이터 공급)
Phase 4. UAE  — Infrastructure 확장     (DRRRK Layer × DMCC Rail × UAE 금융기관)
```

### Phase 2 — 목표 파이프라인 (Closed Loop)

```
실물자산 등록 → 식별·정규화 → 시장가격 추정 → 다수 바이어 견적 수집
→ 실제 거래가격 확보 → 예상가 vs 실제 처분가 비교
→ 유동성·변동성 축적 → "얼마까지 안전하게 금융 가능한가" 기준 생성
```

이 8단계 중 새로 만들 시스템은 거의 없다. 기존 플로우(담보물 등록, 감정가 3-tier, 48h 역경매, 전자계약, 유질 처분)가 이미 각 단계의 이벤트를 생성하고 있고, **빠진 것은 이 이벤트들을 자산 단위로 묶는 정규화된 원장뿐이다.** 테이블 3개 + 주간 배치 1개로 구축 가능하며(무료 티어 수준), 상세 설계는 [구현 스펙 문서](./자산_언더라이팅_원장_구현스펙.md) 참조.

### 지표 전환 — 서비스 지표에서 Underwriting 지표로

| 현재 서비스 지표 | 만들어야 할 Underwriting 지표 |
|---|---|
| 견적 신청 수 | 자산별 Market Value Accuracy (추정 오차 MAPE) |
| 견적 제안 수 | 견적 분산도 (Bid Spread — 유동성·합의도) |
| 판매요청 전환율 | Liquidation Value (바이어 호가 기반) |
| 거래 완료율 | 7/30/90일 처분 가능성 |
| 평균 거래금액 | Price Volatility |
| 바이어 수 | Bid Depth / Recommended Haircut |
| 거래 데이터 | Recommended LTV (카테고리별 안전 한도 커브) |

**하루 1~3건이라는 현재 거래량은 이 지표 체계에서 치명적이지 않다.** 증명 대상이 거래량 성장이 아니라 "적은 거래로도 언더라이팅 데이터가 수렴한다"는 건당 데이터 수율이기 때문이다. 등록 1건 = 가격 이벤트 4~6개(AI 추정 1 + 바이어 견적 3~5, 유찰 건 포함 전부 기록)로 계산하면 연 3,000~4,000 이벤트가 나온다.

### 저거래량 보완 3대 전략 (자본 0원)

1. **견적 자체가 데이터다** — 거래 성사 여부와 무관하게 대부업 전문가의 가격 라벨을 수집. 유찰 건 기록이 규율의 핵심.
2. **파트너 전당포 과거 장부 백필 (최대 레버리지)** — 전당포는 수년치 [감정가→대출→유질→처분가] 기록 보유. 2~3곳 백필이 자체 거래 3년치보다 빠르다. 대가는 현금이 아닌 Prime 우대·수수료 감면·AI 담보가치 도구 우선 제공.
3. **외부 실현가 캘리브레이션** — KREAM·번개장터·Chrono24 sold 데이터로 Market Value 기준선 구축. 자체 견적 데이터와의 격차가 곧 "도매 할인율(wholesale discount)" 관측치가 된다.

### Phase 3 — Financial PoC (국내 임팩트의 완성)

수백억 대출이 실행될 필요 없다. 필요한 문장은 하나다:

> **"금융기관이 드르륵의 자산 데이터를 실제 underwriting에 사용했다."**

실행 형태: 국내 금융회사(저축은행·캐피탈·온투업 등) 1곳과 **Asset Valuation / Underwriting API PoC**. 드르륵은 "이 자산의 Liquidation Value는 X원, 평균 처분기간 Y일, Net Recovery Value Z원"까지만 제공하고, LTV·승인은 금융기관이 결정한다 (UAE 규제 구조와 동일한 역할 분담을 국내에서 미리 연습하는 효과).

이후 Shorooq 피치가 완전히 달라진다:

> "We have underwritten N physical assets in Korea. Our liquidation value prediction has X% accuracy. We observe quotes from Y professional buyers per asset. Financial institutions already use our asset data for credit decisions. Now we plug this underwriting layer into UAE's existing collateral infrastructure such as DMCC Tradeflow."

## 4. Gemini 문제 — 식별과 가격 산정의 역할 분리

사진→가격 one-shot은 원리적으로 부정확하다 (LLM은 시세 테이블이 없고 상태·구성품·연식별 수십 % 격차를 반영 못함). 재설계:

```
[사진] → Gemini: 식별·정규화만 (브랜드/모델/레퍼런스 추출 → canonical_asset_id 매핑)
[가격] → 원장 조회: ① 자체 견적·낙찰 이력 ② 외부 sold comps ③ 상태등급 조정계수
       → 출력은 항상 구간 + 신뢰도 (점추정 금지)
       → 데이터 없는 모델: "추정 불가 — 바이어 견적으로 확인" (정직 표시)
```

바이어 견적 도착 = ground truth 라벨링. `ai_estimate` vs `buyer_quote` 오차가 자동 계산되어 주간 배치에서 조정계수를 갱신한다. **역경매 구조 자체가 자기 교정 루프다.** 기존 감정가 3-tier 구조(§2.5)는 유지하되 산출 방법만 원장 기반으로 교체.

## 5. UAE Go/No-Go 검증 질문 (Feasibility 문서 승계)

국내 Phase 2~3과 병행하여 이메일/미팅으로 확인 (비용 0원):

1. **UAE 규제**: Licensed Finance Company가 개인 보유 luxury watch·jewellery를 담보로 Retail Finance를 제공할 수 있는가?
2. **금융기관**: 왜 UAE 금융사는 Gold는 담보로 받는데 Rolex는 받지 않는가? — 답이 "가격 표준·인증·회수 데이터 부재"라면 드르륵의 존재 이유가 강해지고, "규제"라면 구조를 바꿔야 한다.
3. **DMCC**: Tradeflow Warrant/Collateral 구조를 개인 보유 non-commodity premium asset까지 확장할 수 있는가?
